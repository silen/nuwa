# Phase 4 Prompt

你是资深 Go 框架工程师、开源维护者、长期基础设施项目 owner。请对仓库 `github.com/silen/nuwa` 执行“非兼容性重构”的第 4 阶段。

参考结构风格：

https://github.com/gin-gonic/gin

## 全局背景

默认 `Phase 1` 到 `Phase 3` 已完成：

1. 结构审计完成
2. 根包已瘦身
3. 基础设施包已迁移和重命名

## 本阶段目标

整理横切能力，把中间件、绑定和内部实现归位，进一步降低耦合。

## 本阶段必须完成的事项

1. 将 `router/handler/*` 重构为 `middleware/*`
2. 检查并整理 `request id` 中间件：
   - 保持日志上下文能力
   - 保持 header 行为清晰
   - 不泄露敏感信息
3. 检查并整理 `token` 中间件：
   - 错误处理明确
   - 行为边界清晰
   - 与 token 相关能力职责分离
4. 如果 validator 更适合拆到 `binding/validator.go`，则完成拆分
5. 将不适合公开暴露的辅助实现迁移到 `internal`
6. 清理历史兼容桥接、过渡层、遗留结构

## 本阶段必须遵守

1. `middleware` 目录语义必须清晰
2. `internal` 只放不应暴露的实现细节
3. 不要制造新的“万能公共包”
4. 不要把内部辅助重新塞回根包

## 本阶段输出要求

1. 中间件设计说明
2. `binding` 和 `internal` 的职责说明
3. 清理掉的遗留结构清单
4. 主动破坏兼容点清单
5. 阶段测试结果

## 阶段性验证

1. 中间件测试可运行
2. 包边界清晰
3. 无明显多余桥接代码

## 执行要求

请直接修改仓库，不要只给建议。
这个阶段的重点是横切能力归位和边界清理，不要回退到旧结构。
