# Prompts Usage

这些文件用于把 `nuwa` 的非兼容性重构拆成可分阶段执行的任务，适合投喂给 Cursor、Codex、Claude 等 agent。

## 文件说明

- `phase-1.md`
  - 架构审计与重构蓝图
- `phase-2.md`
  - 根包瘦身与核心框架重组
- `phase-3.md`
  - 基础设施包重构与目录迁移
- `phase-4.md`
  - 中间件、绑定、内部实现清理
- `phase-5.md`
  - 收尾、格式化、测试、最终报告
- `../REFACTOR_PHASED_PROMPT.md`
  - 总版 prompt，适合一次性交给 agent

## 推荐执行方式

推荐按阶段逐步执行，不要一次性把 5 个阶段全部塞给 agent。

推荐顺序：

1. 先执行 `phase-1.md`
2. 检查输出的架构分析和迁移计划
3. 确认方向后执行 `phase-2.md`
4. 依次推进到 `phase-5.md`

## 每阶段的投喂建议

每次只提供一个阶段文件，并附带一句明确指令，例如：

```text
请严格执行这个阶段，不要提前做后续阶段的大规模改动。完成后输出阶段结果、风险和测试情况。
```

如果 agent 容易一次改太多，可以再补一句：

```text
只允许在当前阶段范围内修改代码，超出范围的内容列入后续待办，不要提前重构。
```

## 每阶段结束后的人工验收建议

### Phase 1

检查：

1. 是否真正读过当前代码结构
2. 是否把问题说清楚
3. 是否给出了可执行的迁移计划

### Phase 2

检查：

1. 根包是否已经明显瘦身
2. 是否删除了 `Controller` / `Service` / `Model`
3. 是否删除了 panic 正常控流

### Phase 3

检查：

1. `pkg` 是否已被拆解
2. 是否清除了 `nwHttp`、`cilickhouse` 这类命名问题
3. 是否拆掉了 `tools`

### Phase 4

检查：

1. 中间件是否迁移到 `middleware`
2. `binding` / `internal` 边界是否清晰
3. 是否仍有过渡性脏结构残留

### Phase 5

检查：

1. 是否执行了 `gofmt`
2. 是否执行了 `go test ./...`
3. 是否输出了完整破坏兼容点清单和目录树

## 实战建议

1. 如果 agent 在某一阶段偏离范围，直接回滚到上一步结果，重新只投该阶段 prompt
2. 如果仓库较大，优先要求 agent 在阶段结束时给出变更摘要和未完成项
3. 对于 `Phase 2` 和 `Phase 3`，最好要求 agent 在提交前先列出“将删除哪些旧结构”
4. 如果要降低风险，可以每个阶段单独 commit

## 备注

这些 prompt 默认前一阶段已经完成。

如果你跳阶段执行，建议在发给 agent 时补充一句：

```text
前置阶段尚未执行，请先自行补足必要上下文，但仍只交付当前阶段范围内的修改。
```
