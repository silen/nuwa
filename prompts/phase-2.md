# Phase 2 Prompt

你是资深 Go 框架工程师、开源维护者、长期基础设施项目 owner。请对仓库 `github.com/silen/nuwa` 执行“非兼容性重构”的第 2 阶段。

参考结构风格：

https://github.com/gin-gonic/gin

## 全局背景

这是 Go 基础设施 / 框架仓库重构，不是业务系统模板改造。

本次重构明确允许：

1. 不保留旧包路径兼容
2. 不保留旧 API 命名兼容
3. 允许删除不合理抽象
4. 允许重写测试

但必须保证：

1. 代码生产可用
2. 风格 idiomatic Go
3. 优先标准库和现有依赖
4. 不引入不必要复杂度

## 当前阶段前置假设

默认 `Phase 1` 已完成，并已明确：

1. 当前架构问题
2. 目标架构
3. 目录迁移计划

如果未完成，请先补齐这部分分析后再继续。

## 当前核心问题

1. 根包 `nuwa` 职责过重
2. 根包混合 app lifecycle、engine、validator、autoroute、response、code、controller/service/model
3. 存在 `StopRun()` 和 panic 控流
4. 存在 `Controller` / `Service` / `Model` 这类不符合 Go 基础设施项目风格的基类设计
5. 存在较强的全局状态和隐式初始化

## 本阶段目标

把根包重构成类似 Gin 的框架核心层，只保留真正属于框架核心的能力。

## 根包目标方向

根包建议按能力拆分为清晰文件，例如：

```text
nuwa.go
engine.go
run.go
mode.go
recovery.go
autoroute.go
validator.go
response.go
code.go
```

## 本阶段必须完成的事项

1. 重组根包文件职责
2. 删除 `Controller`
3. 删除 `Service`
4. 删除 `Model`
5. 删除 `StopRun()` 及相关 panic 控流
6. 重写响应辅助逻辑，避免依赖基类方法结束流程
7. 将模式、恢复、启动逻辑拆开
8. 减少或移除全局 engine 与隐式初始化
9. 让核心结构更接近 Gin 的“根包承载框架核心能力”的组织方式

## 本阶段必须遵守

1. 不允许继续保留 panic 作为正常分支控制流
2. 不允许保留明显不合理的基类模式
3. 不要为了兼容旧 API 再包一层旧结构
4. 不要在此阶段提前大规模重构所有基础设施包

## 本阶段输出要求

1. 新的根包职责说明
2. 删除了哪些旧抽象
3. 主动破坏兼容点清单
4. 阶段测试结果
5. 还未处理的包级问题

## 阶段性验证

1. 根包文件职责清晰
2. 无循环依赖
3. 与根包相关的测试尽量修复到可运行

## 执行要求

请直接修改仓库代码，不要停留在建议层。
优先完成根包瘦身，不要在这个阶段把主要精力放到 `pkg` 全量迁移。
